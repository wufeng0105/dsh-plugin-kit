# AGENTS.md（模板）

> **怎么用**：把本文件复制到你的插件项目根目录，重命名为 `AGENTS.md`（去掉 `.template`）。
> 它会随每次运行自动注入，AI 一开工就能看到这五条。
>
> 长内容不在这里——它们在 `plugin-kit` 技能里，需要时按描述自动加载。
> 如果你的技能不在 `.dsh/skills/`，把下面路径改掉。

---

## 插件开发约定

本项目开发 DSH 插件时遵循 `plugin-kit` 技能（`.dsh/skills/plugin-kit/SKILL.md`）。

### 最常踩的五条（每次都要看）

1. **每条验收必须能判真假**；靠人看的必须给机判替代，否则标「人工判读」。
2. **每条关于宿主的断言必须带出处**（探测命令+返回，或安装包 `文件:行`）。
3. **每阶段结束开一个独立审查员**：它不写代码、只读产物、只出三态结论。
4. **任何检查先证明它会红**，再用它判通过。
5. **模块存在 ≠ 产品在用**：必须证明它在 import 图里可达。

### 开工前

- 读 `plugin-kit` 的 `references/process.md`，按 P0 卡产出需求文档
- 用 `cordis_inspect_list` / `cordis_inspect_query` 探测宿主能力，写进依赖清单
- 有 `UNVERIFIED` 项的，进 P1.5 探针门清零后才写功能代码

### 阶段做完时

> 开一个审查员，按 `plugin-kit` 的 `references/process.md` P\<n\> 出口判据审这一版。
> 需求在 `<需求文件>`，产物在 `<产物目录>`。只读不写，只出三态结论。

**必须是新开的审查员。**

### 交付前

- `npm pack` 后从 tarball 真加载一次
- `files` 与包内文件三方向差集为空
- 交付说明里的命令全部真跑过
- 每个已知缺陷标注是否阻断安装路径

### 不要做

- 不要把"测试全绿"当成"验收通过"
- 不要把"无法判定"写成"通过"
- 不要在没跑过的情况下把命令写进交付说明
