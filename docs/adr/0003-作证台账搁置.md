# 作证台账搁置：好想法、错的证据基础

2026-11-13。曾设想把插件重定义为「宿主作证 witness」：挂 `fs/write-intent`，按写入作者分级（宿主外手写 > 独立会话签发 > 同会话自签红旗），把「验证在案」与「宣称完成」在证据上区分。技术上 rc.2 的接缝支持它（waterfall 事件带 FsTarget 与 actor）。

**搁置理由**：该愿景的痛点论证完全依赖单作者实验记录（AI 伪造门记录 R4、skip 通行证漏洞）——而本仓 `evidence.md` 边界二自认「换人从没真的换过」。一个自己写插件自己用的开发者，日常不会遭遇「AI 伪造审查记录」；把它当核心目标是在为未验证的用户群造产品。**搁置非否定**：机制设计本身成立，错的只是时机判断。

**复活条件**（全部满足才重启）：
1. 多智能体协作成为用户日常（子代理互查、跨会话交接使「谁干的」成为高频问题）；
2. rc.2+ 宿主 `fs/*-intent` 的 actor 字段被实测证实可解出 session 身份（现为 L3 推断）；
3. 与 `dsh-fs-observation-policy` 等已占用 fs 事件门的插件共存，slot 竞争行为被实测摸清。

**随附裁定**：接缝迁移（tools/pre-execute → fs/*-intent）随本 ADR 一并搁置——没有台账，迁移没有产品级消费者；P0 的 A9（产品代码零拦截接线）据此直接可达。

## Consequences

- `lib/gate.js`、`lib/ledger.js` 删除；`tools/pre-execute` / `tools/result` 监听器全部移除。
- 本 ADR 是台账相关词汇（witness、would-block、reconciled）的唯一现行解释出处。
- 复活时优先读 stages/p0/需求.md 的历史版本（git）与 2026-11-13 会话的目标推演，避免重走「从拦截开始」的弯路。
