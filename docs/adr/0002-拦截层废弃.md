# 拦截层废弃：fail-closed 与 fail-open 双输，唯一的第三方从未被请出来

2026-11-11 裁定（`evidence/audits/2026-11-11-拦截层存废裁定.md`）删除拦截层，本 ADR 把它升格为永久决策记录并补上 2026-11-13 的最终确认。

**背景**：阶段门曾用 `tools/pre-execute` 在 enforce 模式真拦工具调用。fail-closed 实测：真实会话 17 次拦截 0 次针对产品代码（拦掉的全是只读工具与审查派发本身）；fail-open 实测：shell 通道 4 种常见形态全部绕过文本扫描。「按工具身份猜调用行为」的判据类型在两头都是输。

**2026-11-13 补充**：rc.2 出现了 `fs/write-intent` / `fs/edit-intent` / `fs/delete-intent` 三个结构化接缝（FsTarget 直达文件系统层），技术上解决了「按工具名猜路径」的问题——**但拦截仍然不被 reinstated**：拦截的存在理由（替代信任）已被证伪，接缝只能解决「怎么拦得准」，解决不了「该不该拦」。该接缝的所有权归搁置中的作证台账（ADR 0003）。

**Considered Options**：
- 默认 observe 只记账：执行过（2026-11-11 至 2026-11-13），台账数据最终未被任何产品决策消费，随 0003 搁置。
- 迁移到 fs/*-intent 拦截：拒绝，理由如上。

## Consequences

- `enforce`、`mode` 配置、`GATE_MISSING` 等理由码、`toDecision` 全部从产品代码消失。
- cordis.patch.yml 不再携带任何 mode 字段。
- 未来任何人提议「恢复拦截」时，必须先回答本 ADR 的问题：拦截解决的是「该不该」还是「准不准」。
