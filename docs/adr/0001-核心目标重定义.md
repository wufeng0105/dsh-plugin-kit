# 核心目标重定义：从流程门到黑盒翻译器

2026-11-13。dsh-plugin-kit 原定位是「判据 skill + 常驻纪律 + 台账」三段式（合并自 plugin-kit skill 与 dsh-stage-gate 插件）。经证据复盘裁定：凡被证实的能力都是「证据或证据的纪律」（独立审查员抓 8–12 起真缺陷、readme-claims 防漂移），凡被证伪的都是「替代信任」（拦截 17 次全误、门记录可伪造、台账曾死数月无人知）。**新核心目标：让插件开发者在写代码之前就知道宿主要什么（契约知识），在宣称完成之前就知道要验证什么、怎么验证（可执行验证清单），并且随宿主升级持续保鲜。** 产品形态收敛为：宿主文档可检索副本（dsh-doc 重解）+ preflight 首装自检 + recheck 升级复检 + 把它们注册进宿主 skill 目录的 Host 半。流程分发（九阶段、纪律段、GATE.json 机制）退役。

## Consequences

- 验收表（A1–A10，现住 `evidence/redefinition/需求.md`——原 `stages/p0/需求.md`，该目录约定随机制退役）取代旧的「启动四行日志 + 拦截行为」作为产品完成定义。
- Host 半不再挂任何 pre-execute / tools/result 监听器；inject 只剩 skills。
- skill provider 保留（分发载体），lib/gate.js、lib/ledger.js、lib/discipline.js 删除（git 归档，见 `61f5fa2` / `c98c543` 等父提交树）。
- 独立审查员从产品能力降级为**本仓开发纪律**（协议现住 `docs/reviewer.md`）——它在 P0 审查中一次抓出两条 MAJOR，实证有效，继续用于本仓各节点。
