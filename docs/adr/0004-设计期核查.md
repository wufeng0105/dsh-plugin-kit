# 设计期核查：把两个 skill 的工件做成机判

2026-11-17。把 `domain-modeling` 与 `codebase-design` 的**做法**吸收进本包：新增 `design-check.mjs`（词汇表格式 / ADR 命名与正文 / 标识符样式的弃用名漂移），模板新增 `CONTEXT.md` 词汇表种子，SKILL.md 与模板 AGENTS.md 增加设计期指路。两个 skill 本体不进包、不改动。

## 背景

kit 原先覆盖「写代码（查契约）→ 交付（preflight）→ 维护（recheck）」，缺设计期（做什么、怎么分块）。设计期纪律若只写成文本，会被一次会话读完即忘——本仓已有先例：纪律段（systemPrompt 注入）因「提示可被忽略」退役（ADR 0001）。存活下来的是可执行判定式 + FAIL 附补法：模型在失败点学会规则，不依赖记忆。因此吸收方式 = 把两个 skill 的工件落成可机判的检查，而不是加一段话。

## 取舍

- **纯文本指路**被否决：不可执行，无法对抗「读一次就忘」；用户明确要求落点。
- **`shape.entry` 导出面机判**被砍：独立审计实测 6 个真实插件 3 个假红（含 `__testing` 类合法导出），宿主文档只要求 `apply` + 可选 `inject`/`Config`，且与 preflight 判同一文件会互判打架。入口面归 preflight。
- **`lexicon.drift` 全量扫描**被砍：_Avoid_ 词天生是普通语言词（本仓 README 19/19 命中），全文扫描会 100% 噪声。收窄为只判标识符样式的旧词（含 `_`、`.`、`/`、反引号）——这类旧名出现在正文里永远是错的。
- **不写条件式**（用户拍板）：模板与文档按两个 skill 存在写，不在文本里兜不存在的情况。

## 不可逆代价

格式一旦随 npm 包分发给用户项目，就是用户仓的公共契约：改词汇表条目格式或 ADR 命名规则 = 破坏既有用户仓（他们的 `CONTEXT.md` 会被新版本判红）。因此格式变更只能加宽（兼容旧格式），不能收紧；`--self-test` 与 design-check.test 的合规夹具必须同时保住旧格式。

## 与既有产品的分工（不互判）

- 设计期：design-check —— 词汇表 / ADR / 特征词漂移
- 装前：preflight —— 宿主契约 / 四大装败家族
- 升级后：recheck —— 触点漂移

两两不判同一面；同一项目出现「preflight PASS、design-check FAIL」是正常的（不同阶段）。

## Consequences

- 模板从 4 文件变 5 文件（加 `CONTEXT.md` 种子），SKILL.md 与 README 的计数随之更新，readme-claims 增加 README 侧计数守卫。
- 新骨架首跑 design-check 必红（种子是格式示例）——这是设计期第一步，不是故障；`test/template.mjs` 用「必红」作守卫，`mutate-template` 用「换成真实术语」作红证明。
- 版本按 minor 走（0.3.0），发布时机由维护者定。
