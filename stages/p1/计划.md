# P1 计划：dsh-plugin-kit 重定义实施

> 2026-11-13。依据：`stages/p0/需求.md`（已过审）。本文件回答四个问题：形态怎么定、
> 顺序怎么走、每步完成标志是什么、风险怎么降级。

## 一、形态判断

| 决策点 | 裁定 | 依据 |
|---|---|---|
| **接缝迁移做不做** | **不做**（本轮） | 见下「接缝裁定」——探针前置条件不成立 |
| Host 半保留什么 | 仅 skill provider（`ctx.skills.registerProvider`）+ 版本/加载自检日志 | 新产品只有两样东西：契约知识（skill）与验证脚本（随包分发、用户在终端跑）。纪律段、台账、拦截全部退役 |
| 自检脚本一个还是两个 | **两个，合并分发**：`scripts/preflight.mjs`（首装自检：四大失败家族）+ `scripts/recheck.mjs`（升级复检：触点四态） | 首装与升级的触发时机、输入（无参 vs touchpoints.json）、受众（新手 vs 已有项目）都不同，合并会让两边接口都变复杂；但分发在一起、文档互相指路 |
| 旧机制代码 | git 归档（`77ef98f` 前史 + 本次改造 commit），工作树删除 `lib/gate.js`、`lib/ledger.js`、`lib/discipline.js`，`index.js` 重写 | P0 不做清单已裁定；词汇表标退役 |
| template/ 骨架 | 保留并简化：去掉 `.stage-gate.json`（marker 属于旧机制）与 `stages/`；保留 4 文件（package.json / cordis.patch.yml / index.js / AGENTS.md） | 骨架服务的是「新插件项目怎么起步」，与阶段门无关 |
| 旧 references/ | **不随包分发**：从 skills/plugin-kit/ 移到 `evidence/process-lab-legacy/`（源码仓留档，`files` 白名单不含） | P0 用户可见面裁定：新 SKILL.md 正文不得含旧九阶段导航；判据内容中仍然成立的部分（23 条铁律的通用条目、审查员协议）在新 skill 里以「开发纪律」小节重写收编 |

**接缝裁定（为什么 fs/write-intent 迁移本轮不做）**：
P0 验收表 A9 要求产品代码零拦截接线。fs/*-intent 迁移是为**作证台账**（已搁置）服务的——
没有台账，迁移就没有产品级消费者；`fs/*-intent` 是 single-slot（第一个 guard 赢），
且 desktop profile 已装 `dsh-fs-observation-policy` 占用同一批事件，共存行为未验证。
**裁定：接缝迁移随「作证台账」一并搁置，复活条件相同。** 本轮 Host 半不含任何
pre-execute / fs-intent 接线，A9 的六模式零命中直接可达。
