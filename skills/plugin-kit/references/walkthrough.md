# 实例：一次真实打回

> 这是**唯一一个从真实开发里截下来的完整片段**。
> 看它比看 23 条铁律有效——因为你能看见「自评为什么看不见」。

## 场景

第二轮实验，开发 `draft-studio` 插件（界面型）。

| 项 | 内容 |
|---|---|
| 需求 | `requirements/REQ-02-dsh-draft-studio.md` |
| 阶段 | P3 验证 |
| 开发者的自评 | **「138 个测试全绿，验收分布诚实」** |
| 审查员的判定 | **不通过**：3 BLOCKER / 6 MAJOR / 7 MINOR |

## 审查员发现了什么

### BLOCKER 1：产品没接线

**现象**：

- `lib/writeback.js` 存在，有完整实现
- `test/writeback.test.js` 存在，全部通过
- **但产品代码从来没有 import 过 `writeback.js`**

**后果**：用户点按钮，什么都不会发生。而测试全绿。

**为什么自评看不见**：

自评看的是「测试跑过没有」。测试确实跑过了，而且覆盖了 `writeback.js` 的每个函数。

**但「模块被测试」和「模块被产品使用」是两件事。** 单元测试可以完整覆盖一个没人调用的模块。

**审查员怎么发现的**：

它不是去跑测试，而是问了一个不同的问题：

> 这个模块在 import 图里可达吗？

从产品入口出发往下追，`writeback.js` 不在任何路径上。**测试是从测试文件直接 import 它的——所以测试能过。**

**对应铁律**：接线可达性。

### BLOCKER 2：验收分布造假

**现象**：

21 条验收，自评说「分布诚实」。审查员逐条核对后发现：有几条被归到了「需运行时验」这一档，**而它们其实可以用离线证据判定**。

**为什么自评看不见**：

「需运行时验」是一个**兜底档**。把不好判的项放进去，看起来是「诚实」（我承认没验），实际是把「没做」伪装成「做不了」。

**对应铁律**：验收分类禁兜底。

### BLOCKER 3：防漂移测试造假

**现象**：

有一条测试叫「验证常量与实现一致」。它读了一个常量，然后断言这个常量等于一个写死的值。

**问题**：那个写死的值就抄自被测源码。

**所以这条测试永远不会红**——它验证的是「常量等于它自己」。

**为什么自评看不见**：

测试确实跑了，确实绿了。**但绿的原理是它什么也没验证。**

**审查员怎么发现的**：

它问：「把被测源码改坏，这条测试会红吗？」然后真的去改了。**没红。**

**对应铁律**：防漂移测试不得自带常量。

## 这三条的共同结构

| | 自评检查的 | 审查员检查的 |
|---|---|---|
| BLOCKER 1 | 测试跑过没有 | **产品用没用它** |
| BLOCKER 2 | 分类看起来诚实吗 | **每一类是不是真的只能这么分** |
| BLOCKER 3 | 测试绿不绿 | **把它改坏，会不会红** |

**三个都是「换个问题问」的结果。**

自评问「我做了没有」，审查员问「我做的真的起了作用没有」。

## 这件事怎么用

如果你只记这一页的一件事，记这个：

> **测试全绿是一个状态，不是一项证据。**
> 证据是「把它改坏，它会红」——而这一点必须真的做过。
