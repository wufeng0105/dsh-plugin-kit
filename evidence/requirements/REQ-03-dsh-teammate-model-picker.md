# 需求：dsh-teammate-model-picker（队友模型选择器）

> 一句话：给队友会话（可继续的子代理）加一个模型选择器——队友额度耗尽后，直接换一个有额度的模型让它继续跑；不重建队友、不影响主线会话与全局默认模型。

## 背景（需求的一部分）

队友在被派发那一刻就钉死了当时的模型路由，此后每次唤醒（收到消息 / 恢复运行 / 冷恢复）都走这条已耗尽的路由再失败一次；现有的「切换模型」能力对队友会话明确拒绝。

## 功能

1. 选择器出现在**队友会话**的输入行工具区，显示当前模型 + 推理等级；**只在队友会话渲染**。
2. 两级菜单：模型 / 推理等级；另有「恢复派发路由」清掉该队友的覆盖。
3. 覆盖按队友各自保存，**重启后仍生效**；无覆盖时零介入（派发路由原样生效）。
4. 一个显示开关。

## 硬约束（客户明定的四条）

1. 不改任何官方包。
2. 不引入新的会话事件类型。
3. 无覆盖时零介入。
4. 不动全局默认模型。

## 边界 / 已知限制（验收时的宽容项）

- 不要求与官方选择器像素级一致或键盘序列同源，观感对齐即可。
- 切换在活跃回合中于下一个 step 生效，不中断进行中的请求（对齐官方语义）。
- 模型目录展示全量，不要求白名单联动。
- 暴露给 agent 的换模型操作**不在本期范围**（只有 UI 路径）。

## 验收标准（行为版）

1. 主线会话看不到选择器；队友会话看得到。
2. 给额度耗尽的队友换模型 → 发「继续」 → 队友用新模型跑起来；全程主线会话与全局默认不变。
3. 恢复派发路由后，再「继续」回到原路由（失败如旧）。
4. 重启后覆盖仍在。
5. 无覆盖的队友，行为与未装插件时一致。
