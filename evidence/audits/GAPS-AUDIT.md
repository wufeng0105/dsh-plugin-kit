所以阻断落在第 1 条（漏项：成本、独立性）和第 2 条（不可判：G12、G13）上，各有一条独立成立即阻断，两条同时成立。

## 〇、我核对了什么

判定 FAIL 之前，我做了四件事：

1. **逐条读「怎么算补上」13 遍**，只问一个问题：把这一条交给一个没参与的人，他能不能在某一天明确说「成了」或「没成」。
2. **把 `RETROSPECTIVE.md` 里所有自称「仍成立 / 没做到 / 代价」的句子摘出来**，逐条对清单：§四（四条缺口）、§八（四种自动化）、§九（今天仍未推翻的一条）、§十一（成本对比）、§十二（「永远不该是全自动的」）。
3. **把 `OUTLINE.md` 的三处硬约束对清单**：「不写什么」四条、「给谁看 / 读完能做什么」、以及它自己的「累积矛盾」表（那表说明这个项目把文档内互斥当成缺陷处理）。
4. **用清单自己的两条纪律反查清单**：开头写「每条都标了证据来源，不接受无出处的断言」；「不含已完成的项」。

结论是：这份清单的**证据纪律**是好的（G5 的证据栏甚至给出了「`projen` 出现 0 次」这种可复跑的计数），**结构**是好的（四层分法对得上 方向/机制/交付/方法），但它在**清点范围**上留了一个洞（成本与独立性），在**验收写法**上有两条失效（G12、G13）。前者是漏，后者是自相矛盾。这两样都够阻断。

## 一、完整性

### 1.1 第一条漏项：成本（作者自查第 1 条，成立，且比他写的更严重）

作者写的是「这套东西要求改工作方式（stages/ + GATE.json + marker），维护它自己要花多少时间？清单里一条都没提」。

这句话只说了成本的一半。三份文件里能数出来的成本至少四笔：

| 成本 | 出处（按文字说法） | 清单有没有收款 |
|---|---|---|
| 每次改动都要过的真机验证（约 2 分钟/次，次数无上界） | G13 自己的处方；RETROSPECTIVE §十一 的「装一次约 2 分钟」 | 无 |
| 双份 skill 树的同步与防漂移 | G9 | 只记了「怎么防」，没记「防这件事本身的工时」 |
| 每条新判据要等一次事故才长出来 | OUTLINE 主线「判据要靠事故喂养」；RETROSPECTIVE §十二 | 无 |
| 工作方式改造（stages/、GATE.json、marker）本身的学习与执行摩擦 | 作者自查第 1 条 | 无 |

为什么它算**明显重要**，而不只是「补充维度」：

- 这条主线自己的句子里，成本是**一半**：「把检查从写的人手里拿走……**代价是每道门要人工触发，判据要靠事故喂养**」。清单把收益侧拆成了 13 条，成本侧一条没有。
- `OUTLINE.md` 的分篇表里，`PROCESS.md` 的最后一节「怎么用」**出的问题就是**「用起来会付出什么代价，留给 EVIDENCE」。也就是说，成本是这个组文档**已经承诺要写**的一节内容。它既不在正文（不在我这三份里），也不在缺口清单里，就悬空了。
- 更要紧的是：**P0 的实验设计缺了成本读数就不成立。** G1 的问题是「这东西值不值得做」，而「值不值得」= 收益 / 成本。跑完 P0–P5 只拿到收益侧（判据有没有用、有没有空转），仍然回答不了 G1 自己提的问题。所以成本不是第 14 条，它是 G1 的**同一批数据**。

关于「怎么算补上」，我建议的写法（可判真假）：

> 在一次真实插件开发里记三列：开门次数、每次开门的人工耗时、维护 `stages/`+`GATE.json`+双树同步的耗时。跑完给出「每个需求额外花 N 分钟 / 开 M 次门」，并**事前**写死一个止损线（例如「额外耗时超过需求工期的 30% 则不划算」）。低于止损线 → 机制成立；高于 → 这是方向层面的反证，与 G1 同权。

这条能判真假，而且它一旦写进去，G13 的成本（I5）也就自动受约束了。

### 1.2 第二条漏项：独立性（作者没列进自查，我认为比成本更伤）

`RETROSPECTIVE.md` §九 把这条写成了全文最重的一段：

> `induction/v1.md` 第五节第 1 条：「这套卡是事后归纳的，没有在第二个人身上验证过——可能是『事后诸葛亮』。」**今天仍然成立。**
> `EVIDENCE.md` 的八条边界里也写着：「三轮实验都是同一个作者、同一台机器、同一个 DSH 版本。」

而 §十.2 又说，机制的效力**不是**来自审查员更聪明：

> 审查员之所以有效，不是因为它更聪明，是因为它**没参与写**。

这两句放在一起，就是一处没被清单接住的张力：**「换人」实际只换到了上下文。** 三个阶段是三个子代理，但都是同一个模型、同一个作者写的同一套判据、同一个 DSH 版本。审查员「没参与写」这句话成立；「是另一个人」这句话不成立。

G1 覆盖不到它。G1 的补上条件是「走完 P0–P5 + 拿到 ROADMAP 三条完成标志」，那是一个**真实交付压力**下的项目——仍然是同一个作者、同一台机器。跑完 G1，这条缺口原封不动。

G3 反而**依赖**它。G3 的验收是「可操作到两个人看同一份台账会得出同一结论」——这需要第二个人，而项目自承没有。也就是说：**P0 里有一条的验收条件，依赖一个清单里不存在的资源**。这不是措辞问题，是清单内部的死结。

建议拆法：

> **G1a 真实交付压力未验证**（原 G1）
> **G1b 第二执行者未验证**：换一个作者（或至少换一个模型/另一台机器/另一个 DSH 版本）重跑一次同一批需求，看「门打回的地方」是否重合。重合率低于某个事前写死的比例 → 「结构性」这个归纳前提被证伪。

后者才是这个项目真正的方向赌博：`protocol.md` 规则 4 说「只保留结构性的卡点，结构性 = 换人、换插件仍会再遇到」——**而「换人仍会再遇到」这一半从来没测过**。清单里 13 条，没有一条在测它。

### 1.3 `OUTLINE.md` 那句自认，现在是什么状态（专答）

原句：

> **不写什么**：…… 不写「这套东西能自动运行」（它不是，每道门要人工开）

**判定：部分成立，而被推翻的那一半不是要紧的那一半。**

| 这一半 | 状态 | 依据 |
|---|---|---|
| 「每道门要人工**开**」= 执行侧 | **已被推翻** | `tools/pre-execute` 机械拦；`stages/p<n>/` 未过门写不进去；台账自动记 `skip`/`blocked`/`reconciled`（RETROSPECTIVE §八 四条对照表） |
| 「门要有人**判**」= 判断侧 | **未被推翻** | G8 自承真机已发生「AI 自己写了 `verdict: pass`」——填路条的可以是被审的人 |
| 「这次该不该开门」= 范围侧 | **未被推翻** | G7：`PromptSection.text` 拿不到 cwd，纪律段只能写成条件句，进每个会话 |

所以现在准确的说法是：**这套东西能自动守门，不能自动判门，也不能自动判断「这次改动要不要开门」。**

清单没有处理这个张力。G6 认领的是「拦截有了、提醒没有」，G8 认领的是「pass 能伪造」，两半各占一角，但没有一条说「`OUTLINE.md` 的自认需要重写」。

这件事的严重性不在文风，在于 `OUTLINE.md` 自己规定「**本组文档当一整篇来写。每篇开工前重读本文件**」。它是纪律文件。它现在和实况冲突，而且冲突的方向是**低估**——而这个项目最自豪的是「没有把没做到写成做到了」（RETROSPECTIVE §十.3）。反向的失准（把做到了写成没做到）同样会让下一轮开工时照着错的边界走。

**可执行写法：**

> 在 `PROCESS.md`「怎么用」节写清三档：自动守门（已做）/ 判门与开门范围（未做，靠人）/ 判断本身（永远靠人）。同时给一条反例：G8 的伪造路径。改完 `OUTLINE.md` 的那句话或加一句限定。

**附带一个二选一（这是我认为最该被作者看到的一句）：**

> **G8 与 `OUTLINE.md` 那句自认，只能留一个。**
> 要么补防伪造（G8 从 P3 升级），要么改自认（承认「守的门可以被被审者自己填 pass」）。现在两个都在，等于清单同时承认「自动了」和「自动的那层是假的」，读者无法判断该信哪个。

### 1.4 第三条候选：自动化会切断判据的喂养来源（我认为是漏的，但缺量化事实）

这条纯从三份文件推：OUTLINE 主线说「判据要靠事故喂养」，RETROSPECTIVE §十.1 说 24→67→23，每条都指回一次真实事故。而现在 `tools/pre-execute` 把「忘开门就写产物」这件事**变成不可能**——门不再被打回，也就**不再产出「哪条判据挡住了什么」的记录**。

后果有二：

1. G2（找冗余）在插件上线后变得更难达成：判据不再被真实地考验，就永远「都有用」。这条正好解释了为什么 G2 的验收（I2/M6 那一带）会滑向编造。
2. 机制的学习率下降：越自动化，可喂养的事故越少。

三份文件没有给量化事实（没有「上线后打过几次门」的记录），所以我只把它记为候选，不判它一定该进清单。但至少应有一句：「自动化与判据进化互相拮抗，需要一条观测（每 N 次开发，有多少条判据被真正触发过）」。

### 1.5 计数矛盾：R6（M1 的展开）

- `RETROSPECTIVE` §九：「加上今天真机验证抓出的**六个缺陷**（R1–R6）」。
- 同段随后列了 R1–R5 并说「**五个**都是同一个模式的产物」。
- `GAPS.md` G13：「R1–R5 五个缺陷全是这个模式」。

六和五对不上，R6 从未出现在清单里。这个项目自己立过一条：「`FINAL-REPORT` 写 64 条，实际 67 条 → ✅ 统一」（OUTLINE 累积矛盾表）。同样的错现在换了个数字又出现一次，且就发生在清单里。

它还影响判定：如果 R6 是**同模式**的第六例，G13 的「模式」描述不全；如果 R6 是**另一种**模式，那清单漏了一条缺口；如果 R6 是**现存未修**的缺陷（而不是历史事故），那清单违反了它自己「不含已完成的项」的反面——它含了「未修的项」却没标。

### 1.6 已知边界只进来一条

清单正文里 `EVIDENCE.md` 只被引两处：G1 引「实验设计节」，G3 与 G4 引「边界二（中间态不可复跑）」。而 RETROSPECTIVE §九 明确说 `EVIDENCE.md` 有**八条**边界。

能确认已进清单的边界：**边界二「中间态不可复跑」**（G3、G4 都拿它当理由，这条引对了）。
能确认**没**进清单的边界：**「同一个作者、同一台机器、同一个 DSH 版本」**（1.2 已论）。
剩六条：**缺 `EVIDENCE.md` 全文，这一条无法判断。**

一份自称「当前所有已知不足」的清单，如果不把项目自己写下的「诚实边界」逐条过一遍，那它至少该写一句「本清单已扫过 EVIDENCE 八条边界，其中 X 条转入缺口、Y 条保留为边界」。现在没有这句，所以清点范围不可核（见 1.7）。

### 1.7 清点范围没写，「所有已知」不可核

标题写的是「当前**所有**已知不足」。但全文没有一处说：这份清单是从哪些文档、用什么问题、扫了几遍扫出来的。

对照这个项目自己的标准，这是硬伤：

- 铁律要「可复跑」——别人拿不到你的扫描范围，就无法复跑，也无法说「你漏了」。
- 铁律要「空真排除」——「所有已知不足」是一句**无法被证伪的断言**：只要没找到，就「确实不知道」。这正是它自己在批评的「空真」。

最小补法（一句话）：四层前面加一段「清点范围：扫了 X / Y / Z 三份文档 + 本次会话的 N 次事故，按『结构性 + 可检测』（`protocol.md` 规则 4）筛，剔除 M 条一次性偶发，理由见附录」。这句话一写，1.5 的 R6、1.6 的六条边界就自动有了归属。

## 二、过判

### 2.1 G8（作者自查第 3 条）：**一半对**

作者写：「G8 已经判断超范围，列进清单会不会显得像待办？」

对的那一半：**能力层面确实已经关闭，不该作为「机制缺口」占编号。** 它现在的「怎么算补上」只剩一句「需要一条决策记录」——一个写一段话就能关掉的条目，放在「机制层面」和 G5/G6/G7 并列，读者会以为是一件事。

不对的那一半：**它不该删，该拆。** G8 里有两种东西：

| 内容 | 性质 | 处置 |
|---|---|---|
| 「读懂了规则就能造门」这个能力缺口 | 已决策不做 | 移出清单，标「关闭（2026-xx 决策）」 |
| 「明确不做 ≠ 没想过，需要一条决策记录」 | 真待办 | 保留，但降为文档任务，编号另起（如 D-01） |

作者自己那句「『明确不做』和『没想过』不一样」是对的，值得保留——**错的是位置和优先级，不是存在。**

补一句更要紧的（与 1.3 联动）：G8 不只是「一条注定不做的缺口」，它是**`OUTLINE.md` 那句自认能否成立的反例**。既然真机已经发生过一次 `verdict: pass` 伪造，那「自动守门」守的是一张被审者能自己填的表。所以 G8 现在这个「P3 记录即可」的定级，与 1.3 里那句「部分成立」是互相拖着的：**要么升 G8，要么改自认，不能两个都不动。**

### 2.2 G12（作者自查第 2 条）：**作者的方向对，但问题不是「高估」**

作者问：「『执行者连续犯错』是不是应该归到『人总会犯错』这类无解项，而不是『机制缺口』？」

我的判断：**它同时过度包含和处方错误，光说「高估」会漏掉真正的问题。**

先看它装了什么（原文如实引）：

| 事故 | 属不属于「编辑操作」问题 | 能不能机械防 |
|---|---|---|
| 引用自己撤回的句子（I1） | **不是**。这是「二手结论 / 自述不可信」，机制里已经有对应铁律 | 不能靠编辑检查防；能靠「引用必须给出处」的机械要求防 |
| 切片改文档覆盖掉整节（§九丢失） | **是**。这是破坏性写入 | **能**：整文件写、精确匹配、改后自动 diff 结构，三选一 |
| `ctx.effect` / `log` 接线错误 | **不是**。这是宿主契约接线，属 G13 那类 | 冒烟测试已经抓到了——说明**这一类已有覆盖**，不该拿来证明「机制里没有任何一条判据针对执行者」 |

再看它的处方：「需要一条针对『编辑操作本身』的检查（比如**改完必须重读全文核对结构**）」。

这条处方正好撞在项目自己的主线上。`OUTLINE.md` 的反面写的是「只要规范写得够清楚、让 AI 照着做就够了」，而项目给这条反面的判决是「被材料否证」。归纳聚类 G 也写着「环境隔离只靠自觉」是一类卡点。**「改完必须重读」就是一条靠自觉的规则**——没有任何东西能判它有没有被执行，被跳过了也不会红。用一个被自己否证的方法去补一条缺口，这是清单里最实质的一处内部矛盾。

而且它不可判：什么算「有了这条检查」？写进 skill？写进 23 条铁律？谁来判执行者重读没重读？三个问题都没有答案。这就是阻断项 B4。

建议拆法（拆完只剩一条该留）：

> **G12a 破坏性写入无防护**（保留，P2）：验收 = 制造一次「切片写入会覆盖未声明区域」的尝试，机械上失败或被自动 diff 拦住；或全库改为「改前必须整文件读、改后自动结构核对」的工具约束。**能红能绿。**
> **G12b 自述/引用不可信**（并入既有铁律，不新增）
> **G12c 接线错误**（并入 G13，已由冒烟测试覆盖，删除）

对作者自查那句「人总会犯错」的正面回答：**部分对。** 凡是能被机械检查的（破坏性写入、引用出处、接线），都不是无解项，不该用「人总会犯错」豁免掉；凡是不可能预见的错，确实不该进清单。G12 现在的错，是把两样混在一条里，然后用一个不可判的处方兜住。

### 2.3 G7：**不算过判，但分层错了**

G7 写的是「`PromptSection.text` 拿不到 cwd，所以纪律段只能写成条件句」。它的两难出口是「找到接缝 / 记录为永久边界」，两分支都可观察——所以它**可判真假**，不属于过判。

它也确实不是纯现状描述：G7 自己给了判据——「审计 I1 的严格要求是『非插件项目里不能出现假指令』，条件句只做到『不出现无条件的假指令』」。这是一个**未达标**，不是一句「就是这样」。所以列成缺口合适。

问题只在两处：

1. 它被放在「二、机制层面（影响机制本身对不对）」，却标 P3「记录即可」。层和级自相矛盾。要么它是机制缺口（那它的优先级不该是「记录即可」），要么它是边界（那它该单独一节）。
2. 它已经是 L2 证据（`MERGE-FACTS.md` §十一 F3 探测结论）。**探测做完了，只差一个决策**——和 G8 一样，它实际是「决策未落纸」，不是「未知」。

建议：单开一节「已探明的能力边界」，把 G7 和 G8 的关闭部分放进去。这样四层结构里就不会有「不是缺口的东西占着缺口的编号」。

### 2.4 真正的过判候选：G11（作者没自查到）

G11 的证据栏自己写：「**需要实际核对，未做**」。

也就是说，清单里这一条的成立与否，作者自己不知道。「README 与实际行为**可能**已不一致」——「可能」不是缺口，是待核对。

对比：G6 也有「待决策」的性质，但它的证据是实的（`TRIGGER-PLAN.md` §2.0 有范围决策，`REVIEW-04` 有偏离记录）。G11 没有证据，只有一次推测（改过 `readSkill` 签名）。

补法不是删掉，是**换成一条真能判的缺口**：

> **G11′ 交付文档的断言没有守**（与 G9 同族：都是漂移）
> 验收 = README 里每条行为断言，要么有一条测试/脚本对照它，要么显式标注「不可自动验证」并给出核对日期。对照表建完，README 每条断言有归属。

这样它就和 G9 合并成「文档/产物漂移」的一族，可判、可复跑，也不再靠「可能」。

## 三、优先级

### 3.1 P0 那四条是不是必须做的

**是的，但块内顺序错了，而且这一块少了两样东西。**

G1–G4 确实是同一个实验的四块：G3 定「空转」的判定标准，G4 定记录格式与停止条件，G2 是实验要检验的假设，G1 是实验本体。四缺一，跑完只剩回忆——这个理由成立，P0 定得对。

但清单自己给 P0 的理由是「**它们是同一个实验的四块，缺一样实验就没结论**」。按这条理由，还缺两块：

| 缺的块 | 为什么同属这一块 | 应该的位置 |
|---|---|---|
| **成本基线**（B1） | 没有它，实验只能回答「判据有没有用」，回答不了 G1 自己问的「值不值得」 | P0，与 G1 同一批数据 |
| **G5 仪器校准** | 审查员会自造标准 = 测量仪器未校准；仪器没校，G2 读到的「哪条判据挡住了什么」不可信 | P0（或 P1 之首，但必须在取数之前） |

块内顺序也建议改：**G3 → G4 →（G5）→ G1a/G1b + 成本 → G2**。G2 是结论，不是前置。现在四条并列，读者容易从 G1 开始动手，而 G1 是最后才能做的那条。

### 3.2 有没有被低估的

| 条目 | 现级 | 建议 | 理由 |
|---|---|---|---|
| **G5** | P1 | **P0** | 见 3.1。它决定实验读数可不可信，而这正是 P0 那一块的定义要求 |
| **G13** | P1 | 保持 P1，但**先改验收** | 现在的写法（B5）不可判；且它要的成本无上界（I5）。优先级没错，可判性错了 |
| **成本** | 无 | **P0** | 见 1.1 |
| **独立性 / 第二执行者** | 无 | **P0** | 见 1.2。它是「结构性」这个归纳前提的唯一检验 |

| **G10** | P2 | 可提前到 P1 | 它是 G9 第二条处方的前置；而且「建仓 + tag」是 13 条里最便宜、最不可能返工的一条 |

### 3.3 G6 的位置

G6（只有拦截、没有提醒）留在 P2 合理，但要注意 1.3：**「提醒」不是这条主线的核心成本**。主线的成本是「每道门要人工开」——而开门这件事已经被拦截消掉了（人不用记得，因为写不进去）。缺的那个提醒，实际是「叙事一致性」问题：插件挡住了你，却不告诉你为什么。它更像 G11 那一族（体验/文档），不像方向问题。P2 合适。

### 3.4 一处结构性批评

优先级表只有一列理由，没有「**不补会怎样**」。结果是：P0–P3 的定级不能从 13 条条目本身推出来，只能从那张表反推。而 G5 的错位正好暴露了这个问题——单看 G5 的「为什么算缺口」（审查员会自己发明标准，`induction/v1.md` 当时就问了），它读起来比 G1 更急。

最小补法：每条加一栏「不补的后果」，一句话即可。加完如果 G5 的后果写的是「所有门的结论都不可信」，那它自己就会跳到 P0，不需要争。

## 五、自查三处，逐条判

### 第 1 处：可能漏了成本 —— **对，且低估了**

理由见 1.1。补一句：作者把它写成「可疑点」而不是缺口，等于**给自己留了一个不算数的位置**。§6 的三行没有「怎么算补上」，所以它不占任何优先级，也就不会被做。这是这份清单最典型的自伤：**它用最诚实的方式，把最该做的一条放到了不会被做的地方。**

### 第 2 处：可能高估了 G12 —— **方向对，结论偏**

- 说「对」：G12 里确实有一部分是无解项（「执行者会犯未预见的错」），那部分不该进清单。
- 说「偏」：真正的问题不是「高估」，是**混装 + 处方错误**。三件事里两件不该在「编辑操作」名下；处方「改完必须重读」属于项目自己判死的「靠自觉」类。拆开之后，只有一条该留（破坏性写入），而且它可判、可机械防、该从 P3 提到 P2。

所以准确的自查应该是：「G12 是不是把可解项和无解项装进了一条，并用一个不可判的处方兜住？」——这个问法会直接导向拆分；现在这个问法（「是不是无解项」）只会导向「保留或删除」的二选一，两条路都不对。

### 第 3 处：可能把「明确不做」写成了缺口 —— **对一半**

- 能力层面：对。应关闭、移出缺口编号。
- 决策记录：不对。这是一条真待办，该留，但降为文档任务。
- 作者没意识到的第三层：**G8 是 `OUTLINE.md` 那句自认的反例**。留着它其实是留着一条证据；但既然留着，就不能同时说「自动守门」已经成立。二选一，见 1.3。

### 第四处（作者没想到）：清单的验收依赖一个不存在的资源

G3 的验收是「两个人看同一份台账会得出同一结论」。项目自承：同一个作者、同一台机器、同一个 DSH 版本（`EVIDENCE.md` 边界，经 RETROSPECTIVE §九 引用）。

于是 P0 里出现一个死结：**实验的关键判据，要求一种这个项目没有的资源。** 而清单里既没有「第二个人」这一条缺口（1.2），也没有说 G3 这条验收准备怎么在缺人的情况下执行（找外部人？用不同模型的子代理？同一人隔一周再看？）。

三种替代都必须写明一种，否则 G3 要么被跳（回到「凭印象」），要么被假执行（自己看两遍）。

**顺带两处更小的、也别漏：**

- **第五处：没有清点范围**（1.7）。「所有已知不足」是一句不可证伪的断言，正好撞在项目自己的「空真排除」上。
- **第六处：没有「不补会怎样」这一栏**（3.4）。所以优先级不能从条目推出，只能从那张表反推——G5 的错位就是症状。
