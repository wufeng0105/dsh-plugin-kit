## 一、这个项目交付的是什么

一个 GitHub 项目最终交付的是**「收件人拿到他那份东西并让它起作用」的全过程**。本包有三类收件人，各自手上只有一部分文件：

| 收件人 | 他手上有什么 | 他读到的是 |
|---|---|---|
| npm 页面 / 源码仓访客 | tarball 内的 `README.md`、`CHANGELOG.md`、`LICENSE`、`skills/` | `README.md` |
| 装进 DSH 后的模型 | 包内 `skills/plugin-kit/` | `SKILL.md` + 三个脚本 + `template/` |
| 要改这个包的维护者 | 整个源码仓 | 其余全部 |

## 二、三个交付面

**已实测**：`npm pack --dry-run --json` 报 `entryCount=69`，逐条比对清单，**无** `docs/`、`evidence/`、`test/`、`scripts/`、`CONTRIBUTING.md`。

- **面 A｜对外承诺面**（`README.md`）
  判据：**读者不需要本仓除包内文件以外的任何东西，就能完成安装并验证。** 只放：这解决什么、怎么装、装上怎么确认、边界、常见失败。
- **面 B｜产品本体面**（`skills/plugin-kit/SKILL.md` + 三个脚本 + `template/`）
  判据：**删掉仓里其他所有文档，产品依然完整可用。**
- **面 C｜源码仓面**（`CHANGELOG.md`、`evidence/`、发布流程、开发纪律、守卫测试）
  判据：**只有要动这个包的人才需要读。**

**重构的定义**：判断每一段内容属于哪个面，让它待在自己的面里。当前的主要问题不是「有历史」，而是**面 C 的内容大量堆在面 A**。

## 九、回滚（v1 此节不成立，已重写）

v1 写「任一步出错：`git checkout .` 回到步骤 2 的绿基线」，**三处破绽**（审计 C2）：

- 步骤 1 的收编发生在基线之前，`git checkout .` 会把它删掉；
- `docs/` 删除一旦成 commit，`git checkout .` 回到的是已删除状态；
- `git checkout .` 不清理未跟踪文件，新建的 `CONTRIBUTING.md` 会残留，而 `release.mjs` 要求工作树干净。

**正确做法**：

| 阶段 | 回滚手段 |
|---|---|
| 步骤 1 之前（当前脏工作树） | 动手前先记录 `git stash create` 或直接先 commit，保证有 sha |
| 步骤 2 基线 | 记下该 sha，此后所有回滚以它为锚：`git reset --hard <基线sha>` |
| 步骤 3–7（未提交） | `git checkout -- <具体文件>`，逐文件，不用 `git checkout .` |
| 步骤 5、7（已提交） | `git revert <commit>`，保留历史；`docs/` 用 `git checkout <基线sha> -- docs/` 可单独捞回 |
| 全部放弃 | `git reset --hard <基线sha> && git clean -fd -- CONTRIBUTING.md` |
